# 2026-07-27

## 18:30 — MixScore source transports: build the turntables, not another crate
**State:** EarCrate already had a receding-horizon live planner, typed DJ technique
names, compiled sample racks, phrase preparation, and a fixed SPSC audio callback.
The committed live phrase nevertheless lowered through MIDI note/rack execution. It
could select and retrigger material but did not preserve independent source playheads,
so simultaneous decks, cue jumps, bounded source loops, hard cuts, and fades were not
one exact execution language.

**Asked planner:** Build the smallest end-to-end implementation that can prove the
missing medium now, reuse every trustworthy existing commodity and EarCrate invariant,
and sweep the active DJ/audio OSS community before choosing new dependencies. The
proof must be testable without private music, retain deterministic receipts and source
identity, avoid callback work, and refuse incomplete execution rather than falling
back.

**Planner said:** Keep the existing planner/crate/callback machinery, but add a sibling
`MixScore` source-transport runtime rather than extending the MIDI lowering until it
resembles a deck. Separate master beat, source beat, and source frame; expose deck
verbs; render N simultaneous channels; reconcile stems to the master; and use a
synthetic two-source performance as the first proof. Reuse ffmpeg, NumPy, SciPy,
SoundFile, source hashes, guarded writes, and the current callback boundary. Evaluate
Signalsmith Stretch and libsamplerate next; study GPL DJ systems without silently
linking them into the core.
